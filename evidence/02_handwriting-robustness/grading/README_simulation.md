## 结论

1. 当前宽容度能吸收"丢失类/风格类"转写缺陷；**吸收不了"关键步骤符号/数字级错读"** → 会把正确答卷误判 partial；
2. 三栏裁剪三路 21/21 全对；F3o 翻转 1 题；整图两路各翻转 2 题 → **裁剪版误判面更小**（与整图读数退化一致）；
3. `(2|BM|)²` 一行是本卡目前最脆弱识别点：8 次读取中 3 次出错
   （v1 单次 / v1 三次 / plus 裁剪 / 官方单次 / 思考开启 均读对；官方三次读成 `½|BN|`、整图 flash/plus 读成 `2|AM|`）；
   注意："F3o 最接近真值"指的是它的 ⊥/CD 等**符号恢复**维度最优（对比 v1 单次丢 4 处 ⊥）；
   **读法质量是逐行独立抽签**——同一次运行可在多数行全胜、在关键行失利；本批 5 处翻案与"关键行被读走样"1:1 对应。决定判分输赢的不是调用形态，而是关键行保真度。
   各形态读错率（本行）：裁剪单次 **0/4**、裁剪三次 **1/2**、整图单次 **2/2**——三次另一次（v1 三次）读对，
   且上一批对比中三次反而比单次读得更全（⊥ 全部读回）→ **不能把该错读归因于"分三次调用"形态本身**；
   输入图完全相同（三张裁剪图 sha256 两形态一致），差异仅在打包次数；更符合"同图同参重复运行本就逐次波动"的既有现象。
   **追加实验（2026-09-11 23:25，15 次：5 组 × 3）**：官方组合 / 单键 / 思考开启 × 三图一包 / 单图中栏 **30/30 全对**——
   参数与形态对读错率均无影响；合并 **23 次读取：20 对 / 3 错（13%）**，3 次错读确认为**逐次随机波动**；
   字形层面（`2` 小而紧凑紧贴 `|`、有重描）是这行成为"抽签点"的合理解释。
   详见 `../重复实验_形态与参数_20260911/README.md`（含判据放大图）。
4. 边界：本仿真只测"正确答卷 + 转写缺陷是否被误判"方向；**未测"错误答卷会不会被判对（抬分）"方向**——那属另一组验收；
