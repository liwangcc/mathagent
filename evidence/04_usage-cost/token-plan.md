# Token Plan 口径：一次批阅吃掉多少 Credits

## 结论先说

**1 Credit 恰好等于 ¥0.01 的按量表价。** 这不是近似——官方文档给的三类 token 同时对上：

| 官方示例（qwen3.6-plus） | token 数 | 按量价格 | 按量金额 | Credits |
|---|---|---|---|---|
| 输入 | 8,349 | 2 元/M | ¥0.01670 | 1.67 |
| 缓存命中 | 40,794 | 0.2 元/M | ¥0.00816 | 0.82 |
| 输出 | 573 | 12 元/M | ¥0.00688 | 0.69 |

三类都满足 `Credits = 按量金额 × 100`（缓存那行反推出 qwen3.6-plus 的缓存价是输入价的 10%）。
所以 Credits 不是另一套计量，就是**按量价格的分数**：把 `usage × 单价` 算出来后乘 100 即可。

套餐的实惠来自倍率，不是算法：

| 档位 | 价格 | 月额度 | 等价按量金额 | 倍率 |
|---|---|---|---|---|
| Lite | ¥39 | 11,500 | ¥115 | 2.9× |
| Essential | ¥79 | 25,500 | ¥255 | 3.2× |
| Standard | ¥139 | 45,000 | ¥450 | 3.2× |
| Pro | ¥499 | 180,000 | ¥1,800 | 3.6× |

（2026-11-01 官网限时价；原价分别是 60 / 120 / 180 / 600 元。个人版自 2026-09-22 起只按月限额，没有周额度。）

## 我们的实测用量换成 Credits

用 [`usage.json`](usage.json) 里的供应商回报值，价格取全球部署（元/百万 token）：
flash 输入 0.80 / 输出 2.70 / 缓存 0.08；max 输入 12.00 / 输出 36.00 / 缓存 1.20。

| 阶段 | 模型 | 输入 | 输出 | Credits |
|---|---|---|---|---|
| 模板 · 层级识别 | flash | 3,502 | 2,153 | 0.86 |
| 模板 · 粗定位 | flash | 3,364 | 4,698 | 1.54 |
| 模板 · 转录 | flash | 9,151 | 1,020 | 1.01 |
| **模板 · 解题** | **max** | 9,105 | 5,274 | **29.91** |
| 学生卷 · 转录（单栏） | flash | 3,696 | 626 | 0.46 |
| 学生卷 · 判分 | flash | 3,280 | 2,961 | 1.06 |

汇总：

| 单位 | Credits | 说明 |
|---|---|---|
| 模板 1 页 | 33.32 | 解题占 29.91 = **90%** |
| 模板 2 页 | 66.64 | |
| 每份学生（两栏转录 + 判分） | 1.99 | |
| 一个班 50 人 | 99.56 | 模板只算一次 |
| **一次批阅（2 页模板 + 50 人）** | **166.20** | |

## 各档位能撑多少

| 档位 | 月额度 | 整班批阅（2 页模板 + 50 人） | 新模板（2 页） |
|---|---|---|---|
| Lite ¥39 | 11,500 | 69 次 | 172 份 |
| Essential ¥79 | 25,500 | 153 次 | 382 份 |
| Standard ¥139 | 45,000 | 271 次 | 675 份 |
| Pro ¥499 | 180,000 | 1,083 次 | 2,701 份 |

参照：一个教师每周批 2 次、4 个班，一个月 8 次整班批阅 = **1,330 Credits**，占 Standard 的 3%。
一个年级 20 位教师共用一个订阅、每月 160 次 = **26,592 Credits**，在 Standard 之内、Pro 的三分之一。

## 缓存与夜间

- **模板解题 80% 缓存命中**：29.91 → 22.05 Credits（−26%），模板 2 页 66.64 → 50.90，整次批阅只降 9.9%
  （因为模板本来就只占一次批阅的 40%）；
- **夜间 4 折**（22:00–08:00，官方限时活动，仅 qwen3.8-max / qwen3.8-flash）：所有阶段 ×0.4，
  整次批阅 166.20 → **60.19 Credits**，同样的钱能跑 2.5 倍。批阅本来就适合排到夜里跑；
- 缓存命中价是输入价的 10%（max 1.20、flash 0.08），所以缓存对输出的作用为零——我们的判分 76% 的钱花在输出上，
  缓存救不了它。

## 订阅和按量是两条钱

生产路线本来就是两条计费线：**模板解题走 Max（Token Plan 订阅），其余 flash 调用走按量**。
一次整班批阅（两页模板 + 100 张图、一人一页）拆开是：

| 计费线 | 内容 | 单次成本 |
|---|---|---|
| 按量 | 模板三调 ×2 + 100 张转录 + 100 份判分 = 159.47 Credits | **¥1.59** |
| 订阅 | 模板解题 ×2 页 = 59.82 Credits | **¥0.185**（¥139 档）／¥0.166（¥499 档） |

订阅只占一成，按量占九成——判分一项就占全部成本的大半。

订阅不是省钱手段，是买上限：

| 档位 | 打平点（每月两页模板次数，按 Max 按量 ¥0.598/次） |
|---|---|
| Standard ¥139 | 232 次 |
| Pro ¥499 | 834 次 |

一个教师每月 8 次整班批阅，Max 全按量只要 **¥4.79/月**，比订阅便宜得多；只有到学校、年级共享、
每月上百次批阅时，订阅才比按量划算。

## 和「¥499 能跑多少 token」的对照

同一条式子（97% 缓存命中、输出占 0.3%）算下来，¥499 / 180,000 Credits 对应：

| 模型 | 可跑 token |
|---|---|
| deepseek-v4.1-flash（闲时 1/4 元） | 130 亿 |
| deepseek-v4.1-flash（忙时 2/8 元） | 65 亿 |
| qwen3.8-flash（0.8/2.7） | 165 亿 |
| qwen3.8-max（12/36） | **11 亿** |

手算 7–8 亿是同一量级，偏保守约 30%：deepseek 的忙时/闲时差价被折叠了，按忙时算是 65 亿、闲时 130 亿。
但这个 token 口径对批阅没有指导意义——批阅的输出占 37%（模板解题 5,274 / 14,379），
不是 0.3%，同样 token 数会贵得多。算钱请用上面的分阶段表。

## 边界

- 价格与档位是 2026-11-01 的官网值，限时活动随时变（夜间折扣、新购价都是「限时」），复算前先看官网；
- 缓存命中率是按「同一模板重复批阅」估的，首批模板不会有缓存；
- 判分那 24 条来自同一批作业，题型单一；
- 个人版条款写明模型输入与生成内容会用于服务改进——学校数据是否接受，是采购前要单独确认的事。
